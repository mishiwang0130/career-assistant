## 二、实现思路

1. **辅导是助手的对话能力，不拆子 Agent**：讲解只加一个「讲解规范」技能与一个读薄弱点的只读工具，
   没有新 Agent、新场景、新入口、新路由、新页面。
2. **薄弱点以 MySQL 为权威**：`get_weak_points` 直接读 F6 的 `knowledge_mastery`。不传关键词时只回
   `weak = 1`；传关键词时按名称匹配该用户全部掌握度记录，命中但不是薄弱点的知识点也带上当前分数与等级，
   这样「Redis 那块的」这类问法不会落空。排序与条数上限都在服务层定死
   （`weak desc, mastery_score asc, id asc`，上限 `app.tutoring.max-weak-points`）。
3. **空状态用返回值表达，不用异常**：没有面试记录 / 没有薄弱点 / 关键词没匹配到，都返回可转述的
   `message`，让模型如实告诉用户而不是编造。
4. **助手技能显式收窄**：助手侧 `enableSkills("tutoring")` 只给这一个技能，并放行技能加载工具
   `load_skill_through_path`；声明式子 Agent 的技能过滤由各自声明单独决定，F2/F3/F5/F6 不受影响
   （用装配测试同时断言两侧）。
5. **记忆只读**：F9 不写记忆、不加写记忆工具、不做偏好沉淀；讲解进度与卡点靠 F6 已装配好的框架召回，
   冲突时以 `get_weak_points` 的结果为准。

## 四、Skill 初始化方式

- `sql/career_assistant.sql` 末尾「F9 专项辅导」段用 `INSERT ... ON DUPLICATE KEY UPDATE name = name`
  写入技能 `tutoring`（`source = 'f9-tutoring'`），技能表由 F2 段建立，本段不重复建表。
- 执行：`mysql -uroot -p career_assistant < sql/career_assistant.sql`，重复执行不产生重复数据，
  也不覆盖人工在表里临时调整过的规则。
- 核对：`SELECT COUNT(*) FROM agentscope_skills WHERE name = 'tutoring';` 恒为 1。
- 技能改规则不需要发版（MySQL 技能仓库热生效）；改提示词或白名单需要重新发布。

## 六、手工验证步骤

1. 走一场模拟面试，在若干知识点上答错或回答「不会」→ `knowledge_mastery` 出现对应薄弱点记录
   （`weak = 1`，掌握度按 F6 口径计算）。
2. 回助手会话问「讲讲我的薄弱点」→ 先定位具体知识点，再类比、举例，最后只出一道练习并给出「怎么算答得好」，
   不推给别的入口、不反问「你想听哪个知识点」。
3. 问「Redis 分布式锁再讲一遍」→ 若该知识点是薄弱点则按上面四步讲；若它不是薄弱点，工具会返回它当前的
   分数与等级，回答同样以工具结果为准。
4. 全新账号（没有任何面试记录）问同样的问题 → 如实说明还没有面试记录、建议先练一场，**不编造薄弱点**。
5. 记忆降级：把 `MEM0_BASE_URL` 指到不可达地址（或 `MEM0_ENABLED=false`）后重启 → 辅导照常可用，
   日志是 warn 而不是异常。
6. 记忆真机召回（可选，本条只验召回可用）：向 Mem0 写入/存在该用户的一条 `FACT` 记忆后提问，
   日志与回答应体现召回片段进入本次调用；与 `get_weak_points` 冲突时以工具结果为准。
