# 求职面试训练助手 · 功能模块与架构（定稿）

> 本文档是需求与架构的唯一依据，不留待定项。
>
> 划分维度是「用户能用的功能」；Harness 能力是这些功能的实现手段，集中在第 6 节，**不单独作为模块排期**。

## 1. 项目定位

网页版求职面试训练助手，多人在线使用、数据按账号隔离，部署在服务器上，不是安装在用户本地的工具。本项目同时是 AgentScope Java 2 Harness 的实践项目：**框架能力尽量用，但每一项都必须有真实业务场景支撑。**

用户使用链路：

1. 上传或在线填写简历（F1）
2. 填写求职目标：目标岗位、目标公司、面试时间、目标难度、当前阶段（F4）
3. 诊断简历、针对目标 JD 做匹配（F2 / F3）
4. 按目标岗位模拟面试，系统根据回答动态追问（F5）
5. 每轮回答得到点评，沉淀薄弱点与掌握度（F6）
6. 按薄弱点生成训练计划，随表现自动调整（F7）
7. 每天收到当日训练提醒（F7 的定时任务）
8. 换会话继续练时，系统记得住薄弱点和偏好（长期记忆）

| 项 | 说明 |

| 项 | 说明 |

| 项 | 说明 |
|---|---|
| 用户操作 | 答完一题立即看点评；面试结束看报告 |

| 页面 | 面试会话内的点评面板 + 报告面板 |

### F7 训练计划

| 项 | 说明 |
|---|---|
| 用户操作 | 给出目标（例如「3 天后面 Java 实习，每天 2 小时」），查看计划与每日任务；收到每日提醒 |
| 系统产出 | 按天 / 主题 / 题型 / 难度划分的计划；表现或时间、JD、岗位变化时重规划并保留调整原因；每日提醒 |
| 依赖 | F6 |
| 规模 | L |
| 页面 | 资料库 → `/plans` |
| Harness 能力 | Plan Mode（只读规划阶段 + 人工确认）、Task List、HITL、长期记忆召回、定时任务（Quartz） |

## 4. Agent 架构

### 4.1 判断规则

「要不要拆子 Agent」按下面三条决定，不为了用而用：

| 情况 | 怎么做 |
|---|---|
| 用户自己会选择「我要做这件事」 | 独立入口 + 专属 Agent |
| 只是要用别的模块已经存好的数据 | 用 Tool 读 MySQL / Mem0，不派子 Agent |
| 当前流程内部需要「另一个角色、另一套提示词与工具、结果还要回到流程里」 | 派子 Agent |

按这条规则，全项目只有一个地方真正需要子 Agent：**模拟面试的评分**。

### 4.2 Agent 清单

| Agent | 触发方式 | 负责 |
|---|---|---|
| 通用助手 Agent | 会话（scene `ASSISTANT`） | F8 自由问答 |
| 简历分析 Agent | 会话（scene `DIAGNOSIS`） | F2 诊断与优化建议 |
| 岗位匹配 Agent | 会话（scene `MATCH`） | F3 对标目标 JD |
| 面试 Agent | 会话（scene `INTERVIEW`） | F5 出题与追问；派生评分子 Agent，产出 F6 点评与报告 |
| 辅导 Agent | 会话（scene `TUTOR`） | F9 讲解、举例、补题 |
| 计划 Agent | 页面按钮触发，非会话 | F7 生成与重规划训练计划 |
| 提醒 Agent | 定时触发，非会话 | F7 每日训练提醒 |
| 评分子 Agent（Evaluator） | 由面试 Agent 派发 | 对每题回答打分、识别薄弱点 |

### 4.3 为什么只有面试用子 Agent

评分同时满足三个条件：一，必须与提问分离，否则同一个 Agent 又当选手又当裁判；二，需要另一套提示词与工具（评分标准 Skill、只读题目与回答）；三，结果要回到面试流程里接着问下一题。

其它场景都不满足：

- 简历优化、岗位匹配、辅导各自只有一个角色，一个 Agent 做完即可。
- 训练计划要用的历史薄弱点、简历、目标，都是别的模块已经存好的数据，**用 Tool 读 MySQL / Mem0 即可，不需要派子 Agent**。

### 4.4 入口与 Agent 的关系

| 东西 | 是什么 | 不是什么 |
|---|---|---|
| 前端入口 | 一个会话的起点，决定开场提示、右侧面板与用哪个 Agent | 不等于一个 Agent |
| 会话 scene | 前端展示 + 初始提示 + Agent 装配的选择键 | —— |
| 专属 Agent | 每个会话场景一套提示词与工具白名单 | —— |
| 子 Agent | 面试流程内部派出去的评分角色 | 不是独立入口 |

用户从「模拟面试」进来，就是面试 Agent 在对话；答完一题，面试 Agent 把评分交给评分子 Agent，拿到结果后接着问下一题。

**不启用**「子 Agent 运行期暴露成入口」（`expose_to_user`）机制：入口统一由前端预设，不做运行期动态生成。

## 5. 前端入口与页面结构

```
功能入口（点一下 = 新建对应场景的会话）
  通用助手  →  ASSISTANT（默认入口）
  简历优化  →  DIAGNOSIS
  岗位匹配  →  MATCH
  模拟面试  →  INTERVIEW
  专项辅导  →  TUTOR

最近会话（历史列表，向下滚动加载更早的会话）

资料库
  我的简历  →  /resumes
  训练计划  →  /plans

求职目标  →  /profile
```

| 模块 | 入口位置 | 点击后 | 路由 |
|---|---|---|---|
| F8 通用助手 | 功能入口 | 新建 ASSISTANT 会话 | `/chat/:sessionId` |
| F2 简历优化 | 功能入口 | 新建 DIAGNOSIS 会话 | `/chat/:sessionId` |
| F3 岗位匹配 | 功能入口 | 新建 MATCH 会话 | `/chat/:sessionId` |
| F5 模拟面试 | 功能入口 | 新建 INTERVIEW 会话 | `/chat/:sessionId` |
| F9 专项辅导 | 功能入口 | 新建 TUTOR 会话 | `/chat/:sessionId` |
| F1 简历中心 | 资料库 | 简历列表 / 编辑 | `/resumes`、`/resumes/:id/edit` |
| F7 训练计划 | 资料库 | 计划与每日任务 | `/plans` |
| F4 求职目标 | 左侧栏底部 | 设置页 | `/profile` |

规则：

1. 一个会话有且只有一个场景，场景决定右侧渲染哪个面板（`ChatView.vue` 的 `SCENE_PANELS`）。
2. 场景没做完的入口不显示，不做点了会报错的按钮。
3. 「新建会话」按钮保留，等价于新建通用助手会话。
4. 不新增顶层独立页面，所有页面都在应用壳内。

## 6. Harness 能力与实现方式

### 6.1 用哪些、怎么实现

| 能力 | 实现方式 | 用在哪 |
|---|---|---|
| Agent 装配 | `agentscope-harness` 2.0.3 的 `HarnessAgent`，每个场景一套提示词与工具白名单 | 全部对话 |
| 会话上下文 | `agentscope-extensions-redis` + Redisson 4.2.0 | 键 `career:agent:{userId}/{sessionId}` |
| 会话消息 | MySQL + MyBatis-Plus（`assistant_message`） | 全部对话 |
| 流式输出 | 框架 `streamEvents(...)` → SSE | 全部对话 |
| 自定义 Middleware | 系统提示词注入、埋点 | 全部对话 |
| 业务 Tool | 自研 `ToolBase` 子类 + `ToolsConfig` 白名单 | F2–F7 |
| 子 Agent | `HarnessAgent.Builder.subagent(SubagentDeclaration)` 代码声明 | 仅 F5 / F6 的评分子 Agent |
| 后台子 Agent 任务 | 子 Agent `timeout_seconds=0` 后台模式 | F6 面试报告 |
| Plan Mode | 框架 `enablePlanMode()`，计划正文落 MySQL | F7 |
| Task List | 框架 `enableTaskList()`，任务落 MySQL | F7 |
| HITL | 框架权限确认 + SSE 下发确认请求 | F4、F7 |
| Skill | `agentscope-extensions-skill-mysql-repository` 的 `MysqlSkillRepository` | F2、F5、F6 |
| 长期记忆 | `agentscope-extensions-mem0` 的 `Mem0LongTermMemory` + 自部署 Mem0 服务 | F6 → F7 |
| 上下文压缩 | 框架 `CompactionConfig`（用默认阈值：50 条触发、保留 20 条） | F5 |
| 大结果卸载 | 框架 `ToolResultEvictionConfig`（用默认阈值：80K 字符） | F2、F5 |
| 工具权限分集 | 每个 scene 一套 Agent 装配 + 白名单 | 全部 |
| 定时任务 | `agentscope-extensions-scheduler-quartz`，CRON 每天 08:00 触发，Quartz 用 JDBC 存储与业务共库 | F7 每日提醒 |

新增依赖只有三个，其余已在父 POM 中：`agentscope-extensions-mem0`、`agentscope-extensions-skill-mysql-repository`、`agentscope-extensions-scheduler-quartz`（均为 2.0.3）。

### 6.2 用哪些框架扩展、装什么

| 扩展 | 作用 | 部署形态 |
|---|---|---|
| AgentScope Redis | Agent 会话状态 | 复用现有 Redis 7.4 |
| AgentScope Mem0 | 长期记忆读写 | 自部署 Mem0（Docker Compose，向量后端 pgvector） |
| AgentScope Skill MySQL | Skill 存储与热更新 | 复用现有 MySQL 8，自动建表 `agentscope_skills` |
| AgentScope Scheduler Quartz | 定时触发提醒 Agent | 复用现有 MySQL 8 作为 Quartz JDBC 存储 |

### 6.3 明确不用的

| 能力 | 原因 |
|---|---|
| Workspace 文件式记忆（`MEMORY.md`、`memory/*.md`） | 网页版多用户系统共用一个工作区，用户之间会串数据 |
| Plan Mode 的工作区文件落盘 | 同上，计划正文改存 MySQL |
| 子 Agent 暴露给用户（`expose_to_user`） | 入口统一由前端预设，不做运行期动态生成 |
| 文件读写与 Shell 工具 | 向模型暴露服务器文件系统与命令执行是纯风险 |
| Sandbox 沙箱与编程题 | 本期不做在线编程题 |
| MCP | 本期不接外部工具 |
| Channels（飞书 / 钉钉等） | 提醒只做站内，不做 IM 推送 |
| 框架 RAG（`Knowledge` / `RAGMode`） | 没有检索场景；该模块在 2.0 已标记 forRemoval |
| 框架自带 `LongTermMemory` 文件实现 | 长期记忆统一走 Mem0 |
| `teamsMode` | 团队协作模式，本场景用不上 |

## 7. 数据存储分工

| 数据 | 存在哪 |
|---|---|
| Agent 会话状态与上下文 | Redis（Redisson） |
| 会话元数据、对话消息 | MySQL（`chat_session`、`assistant_message`） |
| 账号与令牌 | MySQL（`sys_user`、`sys_token`、`sys_refresh_token`） |
| 简历正文与元数据 | MySQL（`resume`）；原始文件在 MinIO |
| 求职目标 | MySQL（`user_profile`） |
| 训练计划与每日任务 | MySQL（`training_plan`、`training_task`） |
| 训练提醒 | MySQL（`training_reminder`） |
| 面试问答、点评、掌握度 | MySQL（权威数据） |
| 薄弱点与偏好（跨会话召回） | Mem0 服务 |
| Skill 内容 | MySQL（`agentscope_skills`） |

原则：**结构化业务数据以 MySQL 为唯一权威**，Mem0 只存可跨会话召回的薄弱点与偏好；Redis 只放会话运行状态，不承担业务事实。

## 8. 开发顺序

| 批次 | 模块 | 理由 | 练到的 Harness 能力 |
|---|---|---|---|
| 第一批 | F4 求职目标 + F2 简历优化 | F1 已完成；F4 很小，F2 直接复用简历解析结果，最快跑通「上传简历 → 得到诊断」 | 业务 Tool、Skill（MySQL 仓库）、Tool Result Eviction、HITL |
| 第二批 | F3 岗位匹配 + F5 模拟面试 | 两块互不依赖，可并行；F5 需要 F4 的目标岗位 | 子 Agent、Compaction、按场景分工具集 |
| 第三批 | F6 面试点评与报告 → F7 训练计划 | F6 依赖 F5，F7 依赖 F6 产出的薄弱点 | 后台子 Agent 任务、长期记忆（Mem0）、Plan Mode、Task List、定时任务 |
| 第四批 | F9 专项辅导 | 依赖 F6 的薄弱点 | 子 Agent 复用 |
