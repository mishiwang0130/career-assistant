# 求职面试训练助手 · 功能模块与架构（定稿）

> 本文档是需求与架构的唯一依据，不留待定项。
>
> 划分维度是「用户能用的功能」；Harness 能力是这些功能的实现手段，集中在第 6 节，**不单独作为模块排期**。

## 1. 项目定位

网页版求职面试训练助手，多人在线使用、数据按账号隔离，部署在服务器上，不是安装在用户本地的工具。本项目同时是 AgentScope Java 2 Harness 的实践项目：**框架能力尽量用，但每一项都必须有真实业务场景支撑。**

用户使用链路：

1. 上传或在线填写简历（F1）
2. 填写求职目标：目标岗位、目标公司、面试时间、目标难度、当前阶段（F4）
3. 在助手里问：「我简历可能被追问什么」「这个 JD 我匹不匹配」「Redis 那块再讲讲」（F2 / F3 / F9）
4. 按目标岗位模拟面试，系统根据回答动态追问（F5）
5. 每轮回答得到点评，沉淀薄弱点与掌握度（F6）
6. 按薄弱点生成训练计划，随表现自动调整，每天收到当日训练提醒（F7）
7. 换会话继续练时，系统记得住薄弱点和偏好（长期记忆）

| 项 | 说明 |

| 系统产出 | 按天 / 主题 / 题型 / 难度划分的计划；表现或时间变化时重规划并保留调整原因；每日提醒 |
| 依赖 | F6 |
| 规模 | L |
| 页面 | 资料库 → `/plans` |
| Harness 能力 | 计划 Agent、Plan Mode（只读规划阶段 + 人工确认）、Task List、HITL、长期记忆召回、定时任务（Quartz） |

## 4. Agent 架构

### 4.1 两条判断规则

**规则一：什么功能值得独立入口？** 只有「有状态的长流程」才配独立入口。一次性分析、问一句就出结论的事，不单独开会话。

| 类型 | 特征 | 形态 |
|---|---|---|
| 长流程 | 有明确阶段与结束条件、跨多轮存状态、产出可回访的资产、用户会反复进入 | 独立入口 + 专属 Agent |
| 一次性任务 | 贴一份材料、问一次、给一份结论 | 由助手 Agent 派子 Agent 完成 |
| 自由答疑 | 没有材料，就是聊 | 助手直接回答，必要时加载 Skill |

**规则二：什么时候派子 Agent？** 三条同时满足才派：材料长或上下文重；需要另一套提示词与工具；结果要回到当前对话继续用。

### 4.2 Agent 清单

| Agent | 触发方式 | 负责 |
|---|---|---|
| 助手 Agent | 会话（scene `ASSISTANT`），应用默认入口 | F8 自由问答；读简历/目标/薄弱点；派发下面两个分析子 Agent；F9 讲解与出题 |
| ├ 简历分析子 Agent | 由助手派发 | F2 简历诊断与优化建议 |
| └ 岗位匹配子 Agent | 由助手派发 | F3 对标目标 JD |
| 面试 Agent | 会话（scene `INTERVIEW`） | F5 出题与追问；派发评分子 Agent，产出 F6 点评与报告 |
| └ 评分子 Agent | 由面试 Agent 派发 | 对每题回答打分、识别薄弱点 |
| 计划 Agent | 计划页按钮触发，非会话 | F7 生成与重规划计划 |
| 提醒 Agent | 定时触发，非会话 | F7 每日提醒 |

### 4.3 为什么这么分

**简历优化、岗位匹配交给助手派子 Agent，不单独开入口**：

1. 它们是一次性任务——给一份简历或一段 JD，产出一份结论，不是需要跨多轮维持状态的流程。
2. 材料长，简历全文和 JD 都很占上下文，交给子 Agent 处理，主对话不被撑爆。
3. 可以并行——用户说「简历和这个 JD 一起看看」，助手同时派两个子 Agent，结果一起回来。
4. 结论要回到对话里继续用——用户看完会接着问「那我该补什么」，这是助手的对话。

**模拟面试单独开入口 + 专属 Agent**：它是有状态的长流程——一轮一题、按表现调难度、结束出报告，用户会反复进入，历史会话还要能回访。这不是派一个子 Agent 能替代的。

**评分必须是子 Agent**：评分与提问必须分离（同一个 Agent 又当选手又当裁判）；评分需要另一套提示词与评分标准 Skill、只读题目与回答；结果还要回到面试流程里接着问下一题。三条全中。

**辅导不拆子 Agent**：讲解就是助手的对话能力，加一个「讲解规范」Skill 和读薄弱点的 Tool 就够了，拆出去只是换个入口。

**跨模块取数据不走子 Agent**：训练计划要用的简历、目标、历史薄弱点，都是别的模块已经存好的数据，用 Tool 读 MySQL / Mem0 即可。

### 4.4 入口与 Agent 的关系

| 东西 | 是什么 | 不是什么 |
|---|---|---|
| 前端入口 | 一个会话的起点，决定开场提示、右侧面板与用哪个 Agent | 不等于一个 Agent |
| 会话 scene | 前端展示 + 初始提示 + Agent 装配的选择键，本期只有 `ASSISTANT`、`INTERVIEW` | —— |
| 专属 Agent | 每个会话场景一套提示词与工具白名单 | —— |
| 子 Agent | 当前对话内部派出去的专业角色 | 不是独立入口 |

**不启用**「子 Agent 运行期暴露成入口」（`expose_to_user`）机制：入口统一由前端预设，不做运行期动态生成。

## 5. 前端入口与页面结构

```
会话入口
  助手        →  ASSISTANT（默认入口）
  模拟面试    →  INTERVIEW

最近会话（历史列表，向下滚动加载更早的会话）

资料库
  我的简历  →  /resumes
  训练计划  →  /plans

求职目标  →  /profile
```

助手开场给四个快捷指令，点了就是往当前助手会话发一句话，不是独立 Agent、不新建其它场景：

- 诊断我的简历
- 分析这个 JD 和我的简历
- 我上次面试哪里最差
- 讲讲我的薄弱点

| 模块 | 入口位置 | 点击后 | 路由 |
|---|---|---|---|
| F8 通用助手 | 会话入口 | 新建 ASSISTANT 会话 | `/chat/:sessionId` |
| F5 模拟面试 | 会话入口 | 新建 INTERVIEW 会话 | `/chat/:sessionId` |
| F2 简历优化 | 助手内（快捷指令或直接问） | 助手派发简历分析子 Agent | `/chat/:sessionId` |
| F3 岗位匹配 | 助手内（粘贴 JD 后问） | 助手派发岗位匹配子 Agent | `/chat/:sessionId` |
| F9 专项辅导 | 助手内（直接问） | 助手加载讲解 Skill 回答 | `/chat/:sessionId` |
| F1 简历中心 | 资料库 | 简历列表 / 编辑 | `/resumes`、`/resumes/:id/edit` |
| F7 训练计划 | 资料库 | 计划与每日任务 | `/plans` |
| F4 求职目标 | 左侧栏底部 | 设置页 | `/profile` |

规则：

1. 会话场景只有 `ASSISTANT` 和 `INTERVIEW` 两个，场景决定右侧渲染哪个面板与用哪个 Agent。
2. 未做完的入口不显示，不做点了会报错的按钮。
3. 不新增顶层独立页面，所有页面都在应用壳内。
4. 快捷指令只是预置消息，复用同一个助手会话。

## 6. Harness 能力与实现方式

### 6.1 用哪些、怎么实现

| 能力 | 实现方式 | 用在哪 |
|---|---|---|
| Agent 装配 | `agentscope-harness` 2.0.3 的 `HarnessAgent`，每个场景一套提示词与工具白名单 | 全部对话 |
| 会话上下文 | `agentscope-extensions-redis` + Redisson 4.2.0 | 键 `career:agent:{userId}/{sessionId}` |
| 会话消息 | MySQL + MyBatis-Plus（`assistant_message`） | 全部对话 |
| 流式输出 | 框架 `streamEvents(...)` → SSE | 全部对话 |
| 自定义 Middleware | 系统提示词注入、埋点 | 全部对话 |
| 业务 Tool | 自研 `ToolBase` 子类 + `ToolsConfig` 白名单 | F2–F9 |
| 子 Agent | `HarnessAgent.Builder.subagent(SubagentDeclaration)` 代码声明 | 助手的「简历分析」「岗位匹配」、面试的「评分」 |
| 后台子 Agent 任务 | 子 Agent `timeout_seconds=0` 后台模式 | F6 面试报告 |
| Plan Mode | 框架 `enablePlanMode()`，计划正文落 MySQL | F7 |
| Task List | 框架 `enableTaskList()`，任务落 MySQL | F7 |
| HITL | 框架权限确认 + SSE 下发确认请求 | F4、F7 |
| Skill | `agentscope-extensions-skill-mysql-repository` 的 `MysqlSkillRepository` | F2、F3、F5、F6、F9 |
| 长期记忆 | `agentscope-extensions-mem0` 的 `Mem0LongTermMemory` + 自部署 Mem0 服务 | F6 → F7、F9 |
| 上下文压缩 | 框架 `CompactionConfig`（默认阈值：50 条触发、保留 20 条） | F5 |
| 大结果卸载 | 框架 `ToolResultEvictionConfig`（默认阈值：80K 字符） | F2、F3 |
| 工具权限分集 | 每个 Agent 一套工具白名单 | 全部 |
| 定时任务 | `agentscope-extensions-scheduler-quartz`，CRON 每天 08:00 触发，Quartz 用 JDBC 存储与业务共库 | F7 每日提醒 |

新增依赖只有三个，其余已在父 POM 中：`agentscope-extensions-mem0`、`agentscope-extensions-skill-mysql-repository`、`agentscope-extensions-scheduler-quartz`（均为 2.0.3）。

### 6.2 框架扩展的部署形态

| 扩展 | 作用 | 部署形态 |
|---|---|---|
| AgentScope Redis | Agent 会话状态 | 复用现有 Redis 7.4 |
| AgentScope Mem0 | 长期记忆读写 | 自部署 Mem0（Docker Compose，向量后端 pgvector） |
| AgentScope Skill MySQL | Skill 存储与热更新 | 复用现有 MySQL 8，自动建表 `agentscope_skills` |
| AgentScope Scheduler Quartz | 定时触发提醒 Agent | 复用现有 MySQL 8 作为 Quartz JDBC 存储 |

### 6.3 明确不用的

| 能力 | 原因 |
|---|---|
| Workspace 文件式记忆（`MEMORY.md`、`memory/*.md`） | 网页版多用户系统共用一个工作区，用户之间会串数据 |
| Plan Mode 的工作区文件落盘 | 同上，计划正文改存 MySQL |
| 子 Agent 暴露给用户（`expose_to_user`） | 入口统一由前端预设，不做运行期动态生成 |
| 文件读写与 Shell 工具 | 向模型暴露服务器文件系统与命令执行是纯风险 |
| Sandbox 沙箱与编程题 | 本期不做在线编程题 |
| MCP | 本期不接外部工具 |
| Channels（飞书 / 钉钉等） | 提醒只做站内，不做 IM 推送 |
| 框架 RAG（`Knowledge` / `RAGMode`） | 没有检索场景；该模块在 2.0 已标记 forRemoval |
| 框架自带 `LongTermMemory` 文件实现 | 长期记忆统一走 Mem0 |
| `teamsMode` | 团队协作模式，本场景用不上 |

## 7. 数据存储分工

| 数据 | 存在哪 |

| 训练计划与每日任务 | MySQL（`training_plan`、`training_task`） |
| 训练提醒 | MySQL（`training_reminder`） |
| 面试问答、点评、掌握度 | MySQL（权威数据） |
| 薄弱点与偏好（跨会话召回） | Mem0 服务 |
| Skill 内容 | MySQL（`agentscope_skills`） |

原则：**结构化业务数据以 MySQL 为唯一权威**，Mem0 只存可跨会话召回的薄弱点与偏好；Redis 只放会话运行状态，不承担业务事实。

## 8. 开发顺序

| 批次 | 模块 | 理由 | 练到的 Harness 能力 |
|---|---|---|---|
| 第一批 | F4 求职目标 + F2 简历优化 | F1 已完成；F4 很小，F2 直接复用简历解析结果，最快跑通「上传简历 → 在助手里得到诊断」 | 子 Agent（简历分析）、业务 Tool、Skill（MySQL 仓库）、Tool Result Eviction |

| 第三批 | F6 面试点评与报告 → F7 训练计划 | F6 依赖 F5，F7 依赖 F6 产出的薄弱点 | 后台子 Agent 任务、长期记忆（Mem0）、Plan Mode、Task List、HITL、定时任务 |
