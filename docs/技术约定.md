# 技术约定

本文档记录 M1 建立并冻结的账号与技术底座约定，后续模块直接复用，不重复定义。

## 统一响应

所有接口响应体统一使用 `Result<T>`：

```json
{
  "code": 200,
  "msg": "成功",
  "data": {}
}
```

- 成功固定为 HTTP 200 且 `code = 200`。
- 业务异常（`BizException`）统一返回 HTTP 200，失败语义全部由自定义 `code` 表达，前端按 `code != 200` 判断失败。
- 错误响应体仍然是 `Result`，`data` 为 `null`。
- 鉴权失败保留 HTTP 401：未登录访问受保护接口、Access Token 失效、Refresh Token 失效都由前端统一按 401 处理登录态。
- 参数校验失败返回 HTTP 400，路由资源不存在返回 404，未捕获的系统异常返回 500。
- Controller 只负责参数校验和调用 Service，不在 Controller 内拼装业务错误。

## 错误码

`ErrorCode` 只保存 `code` 和 `msg`，不携带 HTTP 状态。

```java
public final class ErrorCode {
    private final int code;
    private final String msg;
}
```

错误码实例统一放在 `ErrorConstant`，业务代码使用：

```java
throw new BizException(ErrorConstant.USERNAME_ALREADY_EXISTS);
```

`BizException` 默认返回 HTTP 200，业务错误通过 `ErrorCode.code` 区分；只有需要前端按登录态失效处理的场景才显式指定 `HttpStatus.UNAUTHORIZED`（401），例如 Refresh Token 失效。参数校验、路由不存在、系统异常仍由全局异常处理器返回 400、404、500。

| code | msg | HTTP | 说明 |
|---|---|---|---|
| 200 | 成功 | 200 | 成功响应 |
| 400 | 参数错误 | 400 | 参数校验或请求体解析失败 |
| 401 | 未登录或登录已过期 | 401 | 鉴权失败，显式指定，前端据此刷新或跳登录 |
| 403 | 无权限 | 200 | 业务异常，由 code 区分 |
| 404 | 资源不存在 | 404 | 路由或静态资源不存在 |
| 500 | 系统异常 | 500 | 未捕获的系统异常 |
| 1001 | 用户名已存在 | 200 | 业务异常，由 code 区分 |
| 1002 | 用户名或密码错误 | 200 | 业务异常，由 code 区分 |
| 1003 | 账号已禁用 | 200 | 业务异常，由 code 区分 |
| 1004 | 刷新令牌无效或已过期 | 401 | 登录态失效，显式指定 |

后续模块只追加错误码，不复用已有编号，不修改已有编号含义。

## 公共字段

所有业务表统一包含：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `BIGINT AUTO_INCREMENT` | 主键 |
| `create_time` | `DATETIME` | 创建时间 |
| `create_by` | `BIGINT` | 创建人 ID，0 表示系统或未登录 |
| `update_time` | `DATETIME` | 更新时间 |
| `update_by` | `BIGINT` | 更新人 ID，0 表示系统或未登录 |
| `is_delete` | `TINYINT` | 逻辑删除：0-未删除，1-已删除 |

`create_time`、`create_by`、`update_time`、`update_by` 由 `MetaObjectHandler` 自动填充。`is_delete` 使用 MyBatis-Plus 全局逻辑删除配置，不进行自动填充。

建表模板：

```sql
`id`          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键ID',
`create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
`create_by`   BIGINT       NOT NULL DEFAULT 0 COMMENT '创建人ID，0表示系统或未登录',
`update_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
`update_by`   BIGINT       NOT NULL DEFAULT 0 COMMENT '更新人ID，0表示系统或未登录',
`is_delete`   TINYINT      NOT NULL DEFAULT 0 COMMENT '逻辑删除：0-未删除，1-已删除'
```

表统一使用 InnoDB、utf8mb4、`utf8mb4_general_ci`。归属用户的业务表增加 `user_id BIGINT` 和必要索引。

### sys_refresh_token

```sql
CREATE TABLE IF NOT EXISTS `sys_refresh_token` (
    `id`          BIGINT      NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    `user_id`     BIGINT      NOT NULL COMMENT '用户ID',
    `access_jti`  VARCHAR(64) NOT NULL COMMENT '关联的 Access Token jti',
    `token_hash`  CHAR(64)    NOT NULL COMMENT 'Refresh Token 的 SHA-256 十六进制摘要',
    `expires_at`  DATETIME    NOT NULL COMMENT 'Refresh Token 过期时间',
    `revoked`     TINYINT     NOT NULL DEFAULT 0 COMMENT '是否撤销：0-否，1-是',
    `revoked_at`  DATETIME    DEFAULT NULL COMMENT '撤销时间',
    `create_time` DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `create_by`   BIGINT      NOT NULL DEFAULT 0 COMMENT '创建人ID，0表示系统或未登录',
    `update_time` DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    `update_by`   BIGINT      NOT NULL DEFAULT 0 COMMENT '更新人ID，0表示系统或未登录',
    `is_delete`   TINYINT     NOT NULL DEFAULT 0 COMMENT '逻辑删除：0-未删除，1-已删除',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_sys_refresh_token_hash` (`token_hash`),
    KEY `idx_sys_refresh_token_user_id` (`user_id`),
    KEY `idx_sys_refresh_token_access_jti` (`access_jti`)
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4
  COLLATE = utf8mb4_general_ci
  COMMENT = 'Refresh Token 记录表';
```

## 鉴权约定

- 请求头：`Authorization: Bearer <accessToken>`。
- Access Token 是 JWT，payload 至少包含 `userId`、`username`、`jti`、`iat`、`exp`。
- JWT 密钥来自 `JWT_SECRET`，有效期来自 `JWT_ACCESS_EXPIRE_MINUTES`。
- 服务端使用 `sys_token.jti` 校验 Access Token 是否有效、未撤销、未过期。
- Refresh Token 只保存 SHA-256 摘要，原始值只返回给客户端。
- 刷新使用轮换策略：撤销旧 Access Token 和旧 Refresh Token，签发新 token 对。
- 退出登录撤销当前 Access Token 及其关联 Refresh Token。
- 允许多端登录，每次登录创建独立的 token 对。

配置项：

```yaml
app:
  jwt:
    access-token-expire-minutes: ${JWT_ACCESS_EXPIRE_MINUTES:120}
    refresh-token-expire-days: ${JWT_REFRESH_EXPIRE_DAYS:7}
```

## 环境配置隔离

后端配置按 Spring Profile 拆分：

| 文件 | 环境 | 敏感配置规则 |
|---|---|---|
| `application.yml` | 公共配置 | 只放非敏感公共项，默认激活 `local` |
| `application-local.yml` | 本地开发 | 数据库、Redis、JWT 可使用本地明文默认值 |
| `application-dev.yml` | 开发测试 | 数据库、Redis、JWT 可明文，便于测试环境直接部署 |
| `application-prod.yml` | 生产 | 数据库、Redis、JWT、模型密钥全部强制环境变量 |

切换环境：

```powershell
$env:SPRING_PROFILES_ACTIVE = "local"
$env:SPRING_PROFILES_ACTIVE = "dev"
$env:SPRING_PROFILES_ACTIVE = "prod"
```

生产环境变量：

| 环境变量 | 用途 |
|---|---|
| `MYSQL_HOST` | MySQL 地址 |
| `MYSQL_PORT` | MySQL 端口 |
| `MYSQL_DATABASE` | 数据库名 |
| `MYSQL_USERNAME` | 数据库用户名 |
| `MYSQL_PASSWORD` | 数据库密码 |
| `REDIS_HOST` | Redis 地址 |
| `REDIS_PORT` | Redis 端口 |
| `REDIS_DATABASE` | Redis 数据库编号 |
| `REDIS_PASSWORD` | Redis 密码 |
| `JWT_SECRET` | JWT HMAC 密钥 |
| `DASHSCOPE_API_KEY` | 模型 API Key |

`DASHSCOPE_API_KEY` 在 local、dev、prod 全部只从环境变量读取，任何 YAML 中都不允许写模型密钥明文。

## Redis key 规范

所有 Redis key 必须统一为：

```text
career:{模块}:{业务}:{标识}
```

公共前缀常量：

```java
RedisKeyConstants.PREFIX = "career:";
RedisKeyConstants.AUTH = "career:auth:";
RedisKeyConstants.SYSTEM = "career:system:";
```

本模块未使用业务 Redis key，`RedisUtil` 供后续模块复用。

Redis 客户端统一使用 `StringRedisTemplate`，Redis 中保存的是 JSON 字符串，不再配置 `RedisTemplate<String,Object>` 的默认类型序列化。`RedisUtil` 通过 Spring 容器中的 `ObjectMapper` 统一完成对象与 JSON 的互转。

RedisUtil 按 Redis 数据类型提供独立方法：

| 类型 | 方法 |
|---|---|
| String | `set`、`setIfAbsent`、`get`、`delete`、`expire`、`hasKey` |
| Hash | `setHash`、`getHash`、`getHashAll`、`hasHashKey`、`deleteHash` |
| List | `setList`、`getList`、`pushList`、`sizeList` |
| Set | `addSet`、`getSet`、`hasSetMember`、`removeSet`、`sizeSet` |
| ZSet | `addZSet`、`getZSetRange`、`getZSetScore`、`removeZSet`、`sizeZSet` |

带过期时间的 String 写入方法固定为：

```java
redisUtil.set(key, value, timeout, timeUnit);
```

其中 `timeout` 为 `long` 数值，`timeUnit` 为 `java.util.concurrent.TimeUnit`。

## 接口清单

| 接口 | 方法 | 认证 | 说明 |
|---|---|---|---|
| `/api/auth/register` | POST | 否 | 注册并返回 token 对和用户信息 |
| `/api/auth/login` | POST | 否 | 登录并返回 token 对和用户信息 |
| `/api/auth/refresh` | POST | 否 | 使用 Refresh Token 刷新并轮换 |
| `/api/auth/info` | GET | 是 | 获取当前登录用户 |
| `/api/auth/logout` | POST | 是 | 撤销当前 Access Token 与关联 Refresh Token |

请求字段：

- 注册：`username`、`password`、`nickname`
- 登录：`username`、`password`
- 刷新：`refreshToken`

响应字段：

```json
{
  "accessToken": "xxx",
  "refreshToken": "xxx",
  "tokenType": "Bearer",
  "expiresIn": 7200,
  "user": {
    "id": 1,
    "username": "alice",
    "nickname": "Alice"
  }
}
```

## 账号规则

- 用户名：4-20 位字母、数字、下划线，全局唯一且不区分大小写。
- 密码：6-32 位，BCrypt 加密存储。
- 昵称：1-20 位。
