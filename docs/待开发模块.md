## M16 的实现结果

M16 决定后面所有模块的前端接入方式，已完成并决定后续模块的接入方式；面试、诊断、匹配、Tutor 等场景的面板由 M7/M8/M14 追加。

**后端**

- 新增 `chat_session` 表：`id`（即会话标识）、`user_id`、`scene`、`title`、`last_message_at`、`status` 与六个公共字段
- 新增接口：新建会话（指定 `scene`，返回后端生成的 `sessionId`）、会话列表（`last_message_at` 倒序分页）、重命名、删除；旧的 `DELETE /api/assistant/session` 清空接口下线，语义并入删除
- **会话 ID 改由后端生成**：`assistant_message.session_id` 改为 `BIGINT` 并保存 `chat_session.id`，不建物理外键
- 消息接口改为按消息 ID 倒序返回（第 1 页即最新消息），并在会话不存在、已删除或跨账号时返回 1051，供前端完成会话存在性校验
- 自动标题：标题仍是「新会话」时取首条用户消息归一化后的前 20 个字符，并刷新活跃时间

**前端**

- `DefaultLayout`：左侧栏（新建会话 + 会话列表 + 资料库）+ 右侧主内容区，窄屏侧栏收进抽屉
- 会话 store：会话列表滚动分页、当前会话、草稿态、新建、切换、重命名与删除
- 路由改为分层结构：壳作为父路由，会话与资料库页面作为子路由
- **默认进入新建会话**（草稿态，不落库），第一条消息发出时才创建会话，不自动打开历史会话
- 把 M2 的通用助手页改造为会话类型之一（`scene`：`ASSISTANT`）
- 把 M4 的简历列表与编辑页挪到「资料库」分组

## 并行开发纪律

多个窗口同时开发时，以下文件是所有模块都会碰的共享文件：

`sql/career_assistant.sql`、`common/.../result/ErrorConstant.java`、`docs/技术约定.md`、`frontend/src/router/index.ts`、`frontend/src/views/ChatView.vue`、`frontend/src/layouts/AppSidebar.vue`、根 `pom.xml` 与各模块 `pom.xml`。

规则：

1. 只追加、不重排、不修改别人的行；每个模块在共享文件里用自己的分隔注释标明归属。
2. 错误码按号段分配，禁止跨段占用：1001–1049 账号与鉴权，1050–1099 通用助手与 Agent 通道，1100–1199 求职档案，1200–1299 简历，1300–1399 知识点与题库，1400–1499 诊断与匹配，1500–1599 面试，1600–1699 评价与掌握度，1700–1799 训练计划，1800–1899 记忆，1900–1999 向量检索，2000–2099 治理。
3. 每个窗口从 `dev` 新开分支（`dev-feature/<年月日>-<功能名>`），合并前先同步最新 `dev`。
4. M16 的应用壳已定型：新增会话场景需要同时改 `ChatSceneEnum`、`frontend/src/types/session.ts` 与 `ChatView.vue` 的 `SCENE_PANELS`；资料库页面只需在 `AppSidebar.vue` 注册入口。
